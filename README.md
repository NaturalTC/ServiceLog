# ServiceLog

HVAC service history and tune-up reminders for one-person shops.

ServiceLog is a mobile-first field service management app built with and for a
solo HVAC technician: today's jobs at a glance, each customer's equipment and service
history on site, and automatic seasonal tune-up reminders to past customers.

**Status:** early development. See the [project plan](docs/PLAN.md), [backlog](docs/BACKLOG.md) and
[product vision](docs/VISION.md).

## Project structure
The backend is organized **by feature**, following the
[Spring Boot reference guide](https://docs.spring.io/spring-boot/reference/using/structuring-your-code.html):
each feature package holds its own entity, repository, service, controller and DTOs, so a change
to one feature stays in one place. Code shared across features lives in its own top-level packages.

```
backend/src/main/java/dev/servicelog/
├── ServicelogApplication.java   main class in the root package, so component scanning covers everything
├── auth/            owner login, email verification, password reset
├── customer/        customers, properties, phone numbers, customer search
├── equipment/       equipment at a property (types, serial numbers, warranty)
├── servicerecord/   service visits on a piece of equipment, service history
├── job/             scheduling, rescheduling, double-booking check
├── tuneup/          tune-up due list, reminder emails, unsubscribe
├── ai/              AI drafts of service records (OpenAI), privacy redaction, cost limit
├── photo/           photos on service records: clean-up, thumbnails, signed links, storage
├── sync/            repeat-safe requests for actions taken offline (Idempotency-Key)
├── security/        JWT filter and Spring Security configuration (shared)
├── config/          app-wide beans: clock, async email, business time zone (shared)
└── exception/       shared exceptions and the JSON error handler
backend/src/main/resources/db/migration/   Flyway migrations (V1, V2, ...)
scripts/seed-demo-data.py                  fills an empty database with fake demo data
ai-eval/                                   test set and scorer for the AI service-note feature
frontend/scripts/                          app icons and landing-page screenshots
frontend/src/
├── api/             typed API clients, one per feature
├── auth/            login state
├── components/      shared layout
├── lib/             formatting and small helpers
└── pages/           one folder per feature: customers, equipment, service, jobs
```

Tests mirror the main packages under `backend/src/test/java/dev/servicelog/`.

## Stack
React + TypeScript (Vite, PWA) · Spring Boot (Java 21) · PostgreSQL + Flyway ·
Docker Compose · GitHub Actions

## Run locally
Requires Java 21+, Node 22+ and Docker.

```bash
docker compose up -d                 # PostgreSQL on :5433, Mailpit (dev inbox) on :8025

cp backend/.env.example backend/.env # then fill it in:
#   JWT_SECRET      a long random string: openssl rand -base64 48
#   OWNER_EMAIL     the owner's login email
#   OWNER_PASSWORD  12+ characters; only used to create the account on first start

cd backend && ./mvnw spring-boot:run # API on :8080
cd frontend && npm install && npm run dev   # app on :5173
```

There is no sign-up page: the single owner account is created on first startup from
`OWNER_EMAIL` and `OWNER_PASSWORD`, and a verification email is sent. Remove
`OWNER_PASSWORD` from `.env` afterwards.

**Emails in development** (verification, password reset) never reach real inboxes: Mailpit
catches them all. Open http://localhost:8025 to read them and click their links.

## Deploying
One small server with Docker: Caddy (automatic HTTPS), the Spring Boot backend and
PostgreSQL, deployed by a GitHub Actions workflow. Step by step: [docs/DEPLOY.md](docs/DEPLOY.md).

## Install on a phone
ServiceLog is an installable web app (PWA): no app store needed. Phones only install
apps served over HTTPS, so this works on the deployed site (or `localhost` on a computer).
- **iPhone (Safari):** Share → **Add to Home Screen**.
- **Android (Chrome):** menu ⋮ → **Install app** (or **Add to Home screen**).

It opens full screen with its own icon. The service worker caches only the app's own files,
never customer data. To try the production build locally: `cd frontend && npm run build &&
npm run preview` (http://localhost:4173, with the backend running).

Icons are generated by `frontend/scripts/generate-icons.py` (needs Pillow).

## Demo data
`scripts/seed-demo-data.py` fills an **empty** database with realistic, entirely fake data
through the API: 20 customers in western Massachusetts towns, 34 pieces of equipment, a few
years of service history, and today's schedule (dates are relative to today, and the random
choices are seeded, so it's the same every time). Standard library only.

```bash
# e.g. a separate demo database, so your own data is untouched
docker compose exec db psql -U servicelog -c "CREATE DATABASE servicelog_demo OWNER servicelog"
DB_URL=jdbc:postgresql://localhost:5433/servicelog_demo OWNER_EMAIL=demo@example.com \
  OWNER_PASSWORD='choose-a-password' ./mvnw spring-boot:run -Dspring-boot.run.arguments=--server.port=8082
python3 scripts/seed-demo-data.py --url http://localhost:8082 --email demo@example.com \
  --password 'choose-a-password' --verify-with-mailpit
```

The landing-page screenshots come from that data via `frontend/scripts/capture-screenshots.mjs`
(Playwright; instructions at the top of the file). Point a dev server at another backend with
`API_TARGET=http://localhost:8082 npm run dev`.

## AI service notes
On the service record form, the owner types or dictates what he did ("annual on the burner,
new nozzle and filter, CO 10") and AI fills in the form for him to check before saving.
Customer names, addresses, phones and emails are removed before anything is sent, and the
feature is off unless `OPENAI_API_KEY` is set.

It shipped only after clearing a measured accuracy bar on 36 synthetic notes (with traps
such as parts mentioned but not used) plus a 12-note holdout set: zero invented parts. See
[docs/AI-EVALUATION.md](docs/AI-EVALUATION.md).
